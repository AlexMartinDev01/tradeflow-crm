# TradeFlow CRM 需求模块进度矩阵

> 本文以当前 `main` 真实源码为准。判断“完成”要求：前端可操作、后端有真实业务逻辑、数据可持久化、权限/流程有效，并经过 GitHub Actions Docker 构建校验。

状态说明：
- ✅：核心业务需求已形成可操作闭环
- 🟡：核心已实现，剩余能力主要依赖外部服务、生产基础设施或更高级扩展
- 🔴：仍有明显核心功能缺口

## 当前已完成且容易被旧文档误判为“未完成”的功能

以下能力现在已经真实实现，不应再次作为待办重复开发：

- 客户组织树、母子公司、客户合并
- 联系人离职交接、生日/纪念日提醒
- 客户资料完整度、LTV、潜力评分
- 客户专属价、阶梯价、价格历史、市场适配规则
- 公海池、自动回收、领取、协同人
- 自定义字段必填/唯一/角色可见/可搜索规则
- 自定义联系方式渠道设计器
- 品牌多级经销网络
- 询盘自动分配、首次响应 SLA、输单原因
- 报价底价红线、低毛利/高折扣/特殊账期条件审批
- 合同工作台与合同版本
- HS Code、结构化报关资料
- 可审计汇率表与币种换算
- 部门级 self / department / all 数据范围
- 密码策略、登录失败锁定、强制改密、TOTP 2FA
- 客户回收站、恢复、永久清理
- SQLite 自动/手工备份与离线恢复脚本
- 敏感字段后端脱敏与客户导出权限

## 下一阶段优先级

1. **真实邮件能力（SMTP / Gmail OAuth / Outlook OAuth）**
2. **为移动端配置真实 OCR Provider 并做字段映射验收**
3. **附件对象存储、病毒扫描与异地备份**
4. **ERP / WhatsApp Business / 电商平台等真实授权集成**
5. **生产监控、告警与 PostgreSQL 迁移**

> 外部服务类能力只有在获得真实账号、OAuth Client、API Key 或目标系统接口资料后才会标记为“已接通”；仅存在配置入口不算完成。
